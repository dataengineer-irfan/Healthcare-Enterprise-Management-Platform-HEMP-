# 02_Database_Architecture.md — Database & Data Architecture Specification

## 1. Purpose
This document specifies the PostgreSQL data architecture for HEMP, including schema organization, naming conventions, UUID strategy, indexing, partitioning, metadata, auditing, reporting, and Text-to-SQL optimization principles.

---

## 2. Scope
Applies to all relational databases, schema migrations, DDL scripts, read-optimized reporting models, and AI semantic vector stores within HEMP.

---

## 3. Objectives
- Establish PostgreSQL 15+ as the transactional and metadata core.
- Define a clear multi-schema organizational structure (`kernel`, `metadata`, `domain`, `audit`, `ai`, `reporting`).
- Enforce auditability, optimistic locking, and temporal versioning for enterprise compliance.
- Optimize database layout for hybrid transactional/analytical processing (HTAP) and Text-to-SQL AI queries.

---

## 4. Design Principles
1. **Schema Isolation**: Enforce explicit schema boundaries rather than placing all tables in `public`.
2. **UUIDv4 Primary Keys**: Use standard 128-bit UUIDs for all primary keys to guarantee distributed uniqueness.
3. **AI-Ready Schema**: Map every business table to a metadata definition in `ai.semantic_catalog`.
4. **Immutable Audit Logging**: Record `who`, `when`, `action`, `old_state`, `new_state` for all write transactions.
5. **Declarative Partitioning**: Partition high-volume transactional tables (Audit, Claims, Events) by date range.

## 6. Detailed Schema Specifications

### 6.1 Naming Conventions
- Tables: `snake_case`, singular or plural noun based on context (e.g. `person`, `audit_log`).
- Primary Keys: `<table_name>_id` (e.g., `person_id UUID PRIMARY KEY DEFAULT gen_random_uuid()`).
- Foreign Keys: `<referenced_table>_id`.
- Indexes: `idx_<table_name>_<column_names>`.

### 6.2 Audit Strategy (`audit.audit_log`)
Every transactional entity change generates an immutable log entry:
```sql
CREATE TABLE audit.audit_log (
    audit_id BIGSERIAL PRIMARY KEY,
    trace_id VARCHAR(64),
    user_id VARCHAR(64) NOT NULL,
    action_type VARCHAR(32) NOT NULL, -- CREATE, UPDATE, DELETE, EXECUTE
    entity_id VARCHAR(64) NOT NULL,
    record_id VARCHAR(128) NOT NULL,
    previous_state JSONB,
    new_state JSONB,
    timestamp TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
) PARTITION BY RANGE (timestamp);
```

### 6.3 AI & Text-to-SQL Optimization (`ai.semantic_catalog`)
To enable accurate Text-to-SQL generation without hallucination:
- Column comments (`COMMENT ON COLUMN ... IS '...'`) stored for all table attributes.
- Natural language synonyms and query hints registered in `ai.semantic_catalog`.

---

## 7. Dependencies
- **PostgreSQL 15+** with extensions: `pgcrypto`, `uuid-ossp`, `pgvector` (for vector embeddings).
- **Flyway / Liquibase**: Database migration version control.

---

## 8. Security Considerations
- Database connection strings stored in secure Key Vault / Secrets Manager.
- Row-Level Security (RLS) policies applied to multi-tenant and PHI tables.
- SSL connection mandatory (`sslmode=require`).

---

## 9. AI Considerations
- Text-to-SQL models execute read-only queries against `reporting` schema views or controlled read replicas. Direct `UPDATE` or `DELETE` statements generated by AI are strictly rejected at the database driver level.

---

## 10. Future Enhancements
- Automated table partitioning rollover via `pg_partman`.
- Integration of `pgvector` hybrid search combining BM25 full-text indexing with dense vector embeddings.
